1. Reverify database/container/volume identity, five-Item scope, native processes, ports, and DB sessions. Export `PFT_RUNTIME_ENV_FILE=.env.runtime.production.local`, `PFT_DB_ENV_FILE=.env.runtime.db.production.local`, `PFT_BACKUP_ENV_FILE=.env.runtime.backup.production.local`, `PFT_BACKUP_HOST_DIR=/mnt/c/Users/tianr/PFTBackups/Production`, `PFT_APP_COMMIT=$(git rev-parse HEAD)`, and `PFT_WEB_PORT=3000`. Run `docker compose -f compose.runtime.yml -f docker-compose.production.yml -p pft-runtime config --quiet`, never an unredacted config print.
2. Stop any identified native API/web/jobs writers; if none, record that fact. Verify ports 8000/3000 and old DB application sessions are absent. With the old DB still running, capture a frozen read-only fingerprint using `scripts/pft_m6_fingerprint.py`, take a **new** custom-format dump into the protected Production directory, verify SHA-256/archive/ACL, restore it to a new isolated target, and reconcile its fingerprints. Failure aborts before volume reuse.
   The frozen-source capture uses these commands with a fresh UTC stamp, after all writer checks pass:

   ```bash
   PFT_M6_STAMP=$(date -u +%Y%m%dT%H%M%SZ)
   PFT_M6_DUMP="/mnt/c/Users/tianr/PFTBackups/Production/pft-m6-precutover-${PFT_M6_STAMP}.dump"
   (set -a; source .env.backend.production-backfill.local; set +a; \
     .venv/bin/python scripts/pft_m6_fingerprint.py \
       --output "/tmp/pft-m6-${PFT_M6_STAMP}-before.json")
   (umask 077; set -C; docker exec personal-finance-tracker-db-production-backfill-1 \
     sh -c 'exec pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > "$PFT_M6_DUMP")
   /usr/lib/postgresql/16/bin/pg_restore -l "$PFT_M6_DUMP" >/dev/null
   sha256sum "$PFT_M6_DUMP"
   ```

   Restore this exact archive into a **new** isolated target, rerun the same fingerprint against the restore, and require every table hash and count to match before stopping the old DB.
3. Run `docker update --restart=no personal-finance-tracker-db-production-backfill-1`; stop only `db-production-backfill` using `docker compose --env-file .env.backend.production-backfill.local -f docker-compose.yml -p personal-finance-tracker --profile production-backfill stop db-production-backfill`. Keep jobs stopped. Verify the new DB is the sole running volume owner, migrated schema, legacy-column fingerprints, analytics, proxied status, and read-only UI. Create a migrated-state `extra` backup with `docker compose -f compose.runtime.yml -f docker-compose.production.yml -p pft-runtime run --rm --no-deps jobs python -m api.backup create --kind extra`; this overrides the jobs command and does not start its scheduler.
5. **Second approval point:** after those checks, explicitly authorize Production Plaid sync for the unchanged five active Items. Only then start `jobs` with `docker compose -f compose.runtime.yml -f docker-compose.production.yml -p pft-runtime up -d jobs`. Validate daily backup before sync, institution outcomes, publication/status/UI, and isolated restore. Two subsequent normal daily cycles need roughly 48 hours of actual elapsed time; restart, sleep/resume, offline recovery, and startup catch-up remain M6 acceptance work after authorization.

The risky steps are old-writer shutdown, external-volume handoff, live DDL migration, first Production sync/cursor advancement, and any restore. On failure before new writes, stop the new stack **without `-v`**, remove its stopped DB container, rerun the volume-owner check, and return to the pinned, rehearsed old runtime.
